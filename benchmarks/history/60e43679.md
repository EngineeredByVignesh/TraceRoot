## Scope And Limitations

Controlled evidence replay with real LLMs, local Workflows and remote Vectorize; 2 repetitions in AB/BA order. Four case types cover overlapping known incidents, a known database recurrence, changed deployment image, and different database cause. Known recurrence memories contain explicit benchmark-reviewed rules; this is assisted replay, not production-generalization accuracy.
Fixture evidence calls each wait 8 seconds. Batch-to-report is a polling observation that includes intake, fixture delays and queue wait; it is not pure model latency. Completed-only timing can hide failure: inspect completion counts.
Root cause/fix scores are section-specific regex proxies on one representative workflow per true incident, not expert factual accuracy. Failed or malformed reports remain in denominators. New dataset/scorer/prompt/reuse behavior prevents a controlled comparison with the retained baseline. No repairs were executed.
False reuse is checked on changed-image and different-cause workflows only. Low recurrence hit rate can result from similarity filtering, indexing or rule validation; it is not silently tuned after execution. Retrieval failure must not be counted as a safe success.
Tool counts are actual fixture HTTP requests including retries, not embedding/Vectorize calls. Isolated memory seeds and preflight overhead are separate from scored workflows. No live failure injection or ordinary memory-namespace changes occur.

- Without-memory different-database-cause-r1 suggests checking APP_VERSION while fixing database credentials, without evidence that this setting controls authentication. A passing Fix keyword score does not establish a valid or executed repair. Source workflow: alert-bdf9f9c05bac0b8c40307d4db2ad91147450305e0e026e463377c3c753452a4c.
- All seven known-recurrence workflows that missed reuse had retrieved similarities below the unchanged 0.90 threshold. The two hits were approximately 0.9008. This suggests a sharp, uncalibrated cutoff; it was not lowered during the run.

- Correlation does not consume memory. Arm differences in grouping are generation/timing variation, not evidence that memory improved or worsened classification causally. Total embedding-inclusive cost requires reliable embedding accounting; zero exported usage would remain inconclusive.

### Memory Accounting

Text-call coverage is complete in both arms. Without memory: 22 requests, 19764 input / 3768 output tokens, $0.004078 estimated cost. With memory: 21 requests, 20732 input / 3006 output tokens, $0.004006 estimated cost.

With-memory changes relative to without-memory: input tokens 4.90%; output tokens -20.22%; total text tokens 0.88%; logged text cost -1.77%. Fewer requests therefore did not mean fewer total text tokens.

These are observed arm totals, not matched-workflow causal savings: the arms created different numbers of workflows and generated different reports. Embedding-inclusive cost remains unknown. Grouping accuracy and the documented historical-anchoring error are unchanged by this accounting.
